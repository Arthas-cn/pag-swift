# PAG 格式支持矩阵

本矩阵随 [架构设计](架构设计.md) 的阶段扩充。**当前 P0–P6 已通过，P7 正在扩充格式闭包：公开 PAGLoader 支持静态内容、二维动画轨道及内嵌 bitmap/video 合成；PAGComposition 支持编辑快照，PAGImage 支持静图素材。已支持内容共用直接 Metal drawable 播放核心；SwiftUI/UIKit/AppKit 宿主可见验收已覆盖静态内容、bitmap及三份video样例（含2号图片替换）。** 每个文件的可见验收范围以 P5/P6/P7 记录为准，解码成功不自动等于逐帧画面与完整格式通过。

## P1c 公开载入与解析缓存

P1c 不增加任何 PAG 字节布局假设。`Loading/PAGLoader.swift` 只调用 P1b 完整解码器；URL 和 Data 按完整 SHA-256、limits 与 decoder revision 共享解析。`StableFileReader.swift` 逐块读取普通本地文件，通过描述符和路径的 device/inode、长度、纳秒 mtime/ctime 检测读取期间变化，独立请求始终重读。没有扩展名的真实 red 字节副本可以从 public API 载入，MP4 仍按错误格式拒绝。

`LoadWaiter.swift` 用 Mutex 串行化一次完成或取消，单个等待者取消不影响其他等待者；最后等待者离开才取消共享任务。清理/reload 撤销旧 flight 的写回资格，准备阶段的旧请求也不能重新写入新代缓存。`Caching/ParsedFileCache.swift` 实现按保守字节计费的 O(1) LRU，零预算和超大文档不留存，淘汰不使已返回文件失效。它们属于本库载入合同，不冒充上游格式字段。
