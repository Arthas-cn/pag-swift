## 技术信息

| 项 | 要求 |
| --- | --- |
| 语言 | Swift 6.4。`SWIFT_VERSION = 6.4`，`swift-tools-version: 6.4`，`swiftLanguageModes: [.v6]`。不要改回 6.0 或 5 |
| 并发 | 严格并发，开启 Approachable Concurrency。库默认 isolation 为 `nonisolated`，不要为了界面把整库标成 `@MainActor` |
| 系统 | 最低 iOS 26.0、macOS 26.0。不为更早系统写回退。不扩到 watchOS、tvOS、visionOS |
| 渲染 | Metal。直接画到 SwiftUI、UIKit、AppKit 的显示目标。不做 OpenGL、CGL、Skia。不把离屏出图列为必须能力 |
| 性能 | 播放优先。热路径不要先画到离屏纹理再拷到屏幕，也不要为了播放把像素读回 CPU |
| 界面 | 同一套播放能力要能用在 **SwiftUI、UIKit，以及 macOS 的 AppKit**。三种都是要支持的显示方式，不是只做一种再让调用方自己包一层 |
| 位置 | 库在 `packages/pag-swift`（模块 `pag_swift`）。`app/pag-swift-demo` 只做集成验证 |
| 依赖 | 运行时用系统框架。不依赖 libpag、tgfx、SDWebImage、VAPPlayerKit |

demo 工程里若仍是模板留下的部署版本或旧的 `SWIFT_VERSION`，那不是基线。改工程时对齐上表。demo 自己的界面可以留在主 actor。

## 背景

这是用 Swift 重写 libpag 的经典 PAG 播放，不是给 C++ 库做永久包装，也不是链接 `libpag.a`。PAGX（`include/pagx`）不在范围内。

原版用户能感知的模型是：

- 从路径或字节载入 `.pag`，得到可播放的合成。
- 合成下面是图层树。图层种类包括纯色、文本、形状、图像、预合成。
- 绝对时间是微秒。进度是 `0...1`。两者不是同一个数。
- 缩放有不缩放、拉伸、留边、铺满裁切。
- 可以按可编辑索引替换文本和图片，图片还可以按图层名替换。
- 播放、暂停、停止、重复。重复次数小于等于 0 表示无限重复。
- 播放器可以把某一时刻画到表面上；表面可以不挂视图。视图（原版 iOS 是 `UIView`，macOS 是 `NSView`）只是宿主。
- `.pag` 里可以带视频序列，数据在文件内部，不是旁边再放一个 mp4。
- 桌面 Viewer 另外接受外部 `jpg` / `png` / `mp4` / `mov` 作为图层替换素材。`resources/game.mp4` 就是这种素材。这不是把一支 MP4 当成 PAG 文件来播，也不是去做 VAP 那种左右分屏视频。
- 原版能读出音频字节和标记，但 Cocoa SDK 没有公开的音频播放器。
- 原版没有公开的「替换视频轨」方法。iOS 还有 `PAGImageView`、`PAGDecoder`、磁盘帧缓存；macOS 伞头没有前两个。

VAPPlayerKit 是另一个动效播放器（UIKit + Metal，最低 iOS 15，Swift 5.9）。值得借鉴的是行为，不是它的文件格式，也不要把它的 `PlayerView`、`PlaybackSession` 搬过来：

- 解析结果按文件身份做进程内缓存；同一次加载不要重复解析；文件变了不能沿用旧结果；过期的异步结果不能写回。
- 文本放不下时提供自动字号、单行截断和显式跑马灯，本次均须完成业务入口及实际画面验收。
- 动态内容优先以唯一源图层名称作为字符串 tag；无名或重名槽位用已有可编辑索引派生 `text:<index>` / `image:<index>`，不新增 `.pag` 字段。宿主按 tag 返回类型化的文字、图片或图片 URL；URL 的获取由宿主回调完成，库不发网络请求。本次文字槽验收包括自动字号、单行截断与跑马灯。槽位发现和碰撞规则见[动态内容业务接入](动态内容业务接入.md)。
- 本次要求完成宿主逐帧动图槽位及 SDWebImage 适配：依赖只在 Demo 宿主，库保持零 SDWebImage 依赖。此前延期条款已被本次目标取代。既有 ImageIO 路径保留，但不能替代宿主适配验收。
- 没有占位时，空槽位不挡整段播放。

`.pag` 的字节布局只能以 libpag 源码（从 `PAGFile::Load`、`File::Load`、`Codec::Decode` 往下）或 pag.io 文档为证据。没有证据的字段不要实现成「先能跑」，也不要在文档里补一份凭记忆的字段表。测试用 `resources/` 里的真实文件，或明确标成损坏输入。

## 需要实现的核心功能

- 载入 `.pag`（路径与内存），失败要能区分，不能把残缺结果当成成功。
- 读出合成与图层：尺寸、时长、图层种类、起止时间、可见性，以及文本、图片的可编辑数量。
- 用微秒定位时间，用 `0...1` 表示进度，两者不要混用。
- 播放控制：播放、暂停、停止、重复，以及留边 / 拉伸 / 铺满这类缩放。
- 替换文本、按索引或按名替换图片。外部 MP4、MOV 按原版 Viewer 的替换素材来支持。
- 用 Metal 把画面画到 SwiftUI、UIKit、AppKit 的显示目标上。三种界面看到的是同一套结果，不要各画各的。播放热路径直接画到当前显示目标，不要先画离屏再拷贝。
- 进程内缓存已解析内容，规则见上一节。
- 类型化动态内容：用已有图层名作为 tag 解析文字、图片和图片 URL；文字提供自动字号、尾部截断及超框跑马灯。它是运行时编辑，不添加 `.pag` 字段。
- 占位图，以及可选的 GIF、动画 WebP 动图槽位。宿主可自行链接 SDWebImage 提供素材，组件不依赖它；静图只显示一帧。

## 明确不做

- 不包装、不链接 C++ libpag，不实现 PAGX。
- 不播放 VAP 文件，不用 VAP 的分屏 alpha 和 `AVAssetReader` 管线来播 PAG。
- 不做公开的音频播放器。
- 不把网络下载放进库。
- 不把离屏出图、像素读回当作必须能力。原版有 `MakeOffscreen`，VAPPlayerKit 没有。播放不依赖它；需要导出或截图时再单独立项。
- 形状图层的运行时编辑、命中测试、仅 iOS 的逐帧解码器和磁盘帧缓存，原版有，但不是这份核心说明要求先做的能力。
