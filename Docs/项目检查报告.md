# 项目检查报告（2026-10-23）

## 结论与范围

当前核心合同要求的加载、场景/时间、编辑、播放、三种宿主、动态文字和图片供给均有实现及回归。126 份仓库 PAG 样例在本次审计中全部通过公开加载、首/中/末帧计划及 Metal 输入准备，并额外通过小尺寸缩放宿主路径。**不能据此宣称完整 PAG 格式兼容或所有设备达到 60/120 FPS。**

本次检查覆盖库全部目录的结构/配置/危险模式扫描，并重点阅读加载预算与缓存、播放调度与取消、内容供给、媒体缓存、场景准备、Metal 所有权及 Demo 生命周期。不是对约 3.4 万行生产代码和全部 shader 的逐行形式证明。没有发现可由本轮证据确认的阻断性正确性问题；发现并修复两处性能浪费，删除一处冗余状态。

历史视觉验收以 [动态内容业务接入](动态内容业务接入.md) 末尾“Xcode 原生窗口验收与文字切字修复”“最终窗口复验与交付边界”为准，其中记录了三宿主、动图、文字模式及批播证据。较早“待验收”“受阻”和百分比均属于历史阶段。本次不重复启动、退出或清点 Demo，不把新构建通过冒充新画面验收。

| 范围 | 当前证据 | 尚有边界 |
| --- | --- | --- |

## 已处理问题

### 中：无关编辑重复准备截断文字

位置：[PreparedScene.swift](../packages/pag-swift/Sources/pag_swift/Timeline/PreparedScene.swift)，`PreparedScene.prepare` 的文字复用分支。

之前明确排除了 `.truncate`，并使用产物 `old.style` 判断输入身份。截断产物的文字已经是带省略号的前缀，无法代表完整业务文字。结果是隐藏某层或替换其他素材后，同一文字又执行 CoreText 整形、二分测宽、字形轮廓和适配，产生新资源身份。

最小修复：比较前后合成的完整输入样式和溢出策略，相同时复用已有不可变结果；不新增缓存或状态。完整文字、颜色或布局变化仍失效，命中仍收费并响应取消。

`TruncatedTextReuseTests.visibilityEditReusesTruncatedText` 在修改前失败，修改后通过；同时覆盖尾部变化、颜色变化、切回自动布局、预算不足和取消。

| Debug，相同 TEXT04 长文字，预热 5 次、测量 30 次 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 复用同一文字结果 | 0/30 | 30/30 |
| 重复场景准备中位数 | 1.8384 ms | 0.0058 ms |
| P95 | 2.1591 ms | 0.0075 ms |

此测量只涵盖 CPU 重复准备，不包括显示、GPU 或首次字体建立；不将比例扩展为整段动画加速比。

### 中：宿主静帧摘要复制整份像素

位置：[PAGAnimatedImageSource.swift](../packages/pag-swift/Sources/pag_swift/Media/PAGAnimatedImageSource.swift) 的 `PAGImage.make(from:)`，以及 [DocumentIdentity.swift](../packages/pag-swift/Sources/pag_swift/Loading/DocumentIdentity.swift)。

之前为计算身份把尺寸前缀与全部 RGBA 像素拼到新的 `Data`。公开输入最大 64 MiB，这会新增一份同量级临时载荷。

最小修复：顺序分块哈希前缀和像素，保留原 SHA-256 字节顺序与身份，不分配完整拼接副本；空输入也在进入前检查取消。未宣称进程 RSS 固定下降 64 MiB，实际 allocator 和系统内存尚未单独测量。

`DocumentIdentityTests` 对独立 CryptoKit 拼接摘要验证空输入、块边界及非零起点 slice，并验证宿主帧旧身份不变、同像素不同尺寸身份不同和预取消失败。

### 低：加载请求保存未使用的门闩引用

位置：[PAGLoader.swift](../packages/pag-swift/Sources/pag_swift/Loading/PAGLoader.swift)，私有 `LoadRequest.waiter`。

该字段只在初始化时写入，后续取消通过本地捕获及 `LoadFlight.waiters` 完成。删除字段和初始化参数，保留实际所有者及取消路径。未为减少行数合并不同职责的缓存、删除格式门禁或清理历史证据。

### 中：使用入口缺失、历史状态分散

新增根目录 [使用说明](../USAGE.md) 与 [README](../README.md)，按真实 API 说明绑定时序、值快照、stop/rewind、动态素材时钟、目录索引、异步安装事件和缓存计费。格式矩阵与进度文件顶部新增当前检查入口，历史记录保留。

## 性能现状与下一步

本轮主机为 arm64、macOS 27.0.1（26A434），工具链 Swift 6.4、Xcode 27A9275。探针串行运行，没有与本任务的编译/测试同时进行；未检查或终止用户桌面应用，因此不声称整机空闲。原始报告带实际构建身份。

解析缓存：Debug，每资源 20 对空解析缓存/命中、5 组八路并发，共 320 样本；不清 OS 页缓存。

| test2.pag | 1.3573 ms | 0.0596 ms |
| editing/replace.pag | 7.5756 ms | 0.1514 ms |

20 组八路并发均只有一次解析。命中仍重新读取和校验完整内容；不能为降低这一耗时仅按 URL 或 mtime 复用旧文件。

复杂矢量：500×500、两轮 `0/0/0.25/0.5/0.75/0.99`，关闭 Picture，未提交 GPU，管线编译单列。Debug 首次 Metal 输入准备分别约 272.24 ms（list/14）、441.29 ms（list/17）、599.88 ms（TextDirection）；这些包含网格生成和输入准备，不能称为 GPU 执行时间。

这些结果确认同帧缓存有效，也确认复杂首帧及部分变化帧仍可能超过 16.67 ms 的单次 CPU 工作窗口。实际显示允许合并请求且 Picture 策略不同，因此既不能据此换算屏幕 FPS，也不能称首帧卡顿已经消除。

按优先级保留最多三项后续工作：

1. **高，复杂矢量首帧/动态轮廓成本**：`RenderGeometrySource.prepare`、曲线/描边细分和网格准备是下一轮性能定位对象。先用真实 Release 呈现与调用栈划分冷准备、缓存失效和 GPU，保留几何误差、预算及像素金值，再决定预准备或算法改动。不能只扩大缓存或降低曲线精度掩盖成本。
2. **中，多播放器长期内存与最低系统覆盖**：媒体、几何、Picture、附件池各自有界，但预算跨播放器叠加；需在实际业务并发数下做长期播放/替换与系统内存测量，并分别记录 iOS/macOS 26 的字体和 GIF/WebP 行为。当前单主机测试不替代这项覆盖。
3. **低，Demo 多余 package product**：工程同时链接 `SDWebImageMapKit`，`app/`、`scripts/`、库中没有 MapKit 使用。可在明确工程配置清理时删除该 product 的 target 与 Frameworks 引用，再双平台构建；本次遵守“未要求时不改工程配置”，只记录，没有改 pbxproj 或依赖锁文件。

`PAGComposition.dynamicSlotRecords()` 在查询/编辑时重新扫描排序，属于可测量的后续候选；未进入逐帧渲染，不据此添加全局缓存。不同 LRU 的预算、引用寿命和键语义不同，本次未为了形式统一引入通用缓存抽象。

## 正确性、安全性与维护性

- 输入先检查长度、计数、深度和预算，未知语义失败，不发布半份文档。普通本地文件稳定性校验和取消在后台执行。
- 加载多等待者、播放提交许可、内容会话/版本令牌以及单 GPU owner 已形成明确隔离边界；系统回调不直接修改控制器状态。
- Metal 最终 pass 直接写 drawable；局部附件服务必要效果、整体合成和 Picture，不存在无条件整帧 CPU 读回路径。
- 已有测试区分计划、编码、GPU 完成和实际呈现；异步内容安装事件同样没有冒充显示成功。
- 本次新增/修改的声明和测试场景均有中文 `///`，非显然分块与复用分支有 `//`。生产 Swift 最大文件 629 行，测试最大 711 行，均低于仓库软限制。未向无关文件刷注释。
- 一次定向测试停在系统 CoreText 字体注册服务同步 XPC 等待；采样留存后仅终止本任务的测试进程，独立重跑通过。没有修改系统字体服务或以禁用测试掩盖问题。
