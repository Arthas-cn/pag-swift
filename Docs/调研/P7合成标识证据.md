# P7 合成定义与引用 ID（2026-09-30）

正式Stroke tag21解码门禁通过后，旧SceneValidator把六份真实文件误判为`duplicateOrZeroCompositionID`。本记录修订定义ID不能为0的假设，不增加新字节布局。

只读证据均位于`/Users/arthas/shibo/iOSProject/libpag`：

- `src/codec/tags/VectorCompositionTag.cpp::ReadVectorComposition`、`BitmapCompositionTag.cpp::ReadBitmapComposition`、`VideoCompositionTag.cpp::ReadVideoComposition`直接读取`readEncodedUint32()`作为定义ID，没有排除0。
- `src/base/Composition.cpp::verify`只在共同属性处验证正尺寸、时长和帧率；不要求正ID。
- `src/base/File.cpp::File`将`compositions.back()`设为mainComposition；ID0可以是根，根选择不依赖ID。
- `src/codec/tags/CompositionReference.cpp::ReadCompositionReference`只有正ID才建立引用占位。`src/base/PreComposeLayer.cpp::verify`要求非空composition，`src/codec/Codec.cpp::VerifyCompositionGraph/MeasureCompositionDepth`也拒绝空子合成。因此引用0不能绑定同文件的定义0。
- `Codec.cpp::InstallReferences(const std::vector<Composition*>&)`用`unordered_map.insert`建立索引，相同ID保留首次定义。此分支已取证，但本阶段仍明确`unsupportedFeature("duplicateCompositionID")`；不伪称为上游非法字节。

本轮最小修正：SceneValidator允许定义0，CompositionGraph引用lookup前要求正ID，PAGVideoDecoder删除额外的定义0拒绝；重复定义改为明确未支持。源图层ID策略、父链、根数组顺序和实例身份不变。整个文档仍要先通过全图、深度、数量、时间、资源与取消检查，不能为这六个样例绕过后续错误。
