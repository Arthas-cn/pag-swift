# P7 MergePaths 源码与真实载荷证据

上游只读版本为仓库既定的 libpag 提交。`include/pag/file.h:1569–1582`定义 Merge=0、Add=1、Subtract=2、Intersect=3、ExcludeIntersections=4；`src/codec/tags/shapes/MergePaths.cpp:22–27`只编码一个 `FixedValue<UInt8>`，默认值 Add=1，**没有 flags 或动画轨道**。`ShapeTag.cpp`与`LayerTag.cpp`将 tag24 分发到形状组或形状层；未知 mode 不应退回 Add。

`src/rendering/renderers/ShapeRenderer.cpp:151–173,544–574`按源顺序递归收集当前组已经存在的全部 Path（含子组，不含 Paint），无路径时 MergePaths 不做任何事；有路径时从首路径起，对后续路径依次做 Append、Union、Difference、Intersect、XOR 之一，然后 `group->clear()` 删除此前**所有路径、Paint 和子组**，仅放回一个结果 Path。后续 Fill/Stroke 才消费这个单一路径。把 Boolean 错写成各路径独立绘制、只处理直接子路径、保留合并前 Paint，或把 Append 和 Union 当成同义词，都会改变画面。TrimPaths 若在 MergePaths 后出现，应面对一个结果 Path 而非原路径列表。

现有 `ShapeAnimationInspection`沿容器、Vector、ShapeLayer 与 ShapeGroup 的真实标签边界扫描全部126份资源，`PAG_MERGE_AUDIT=1 swift test --filter PAGMergeEvidenceTests`的只读记录为`/tmp/pag-swift-merge-evidence.log`：**84个**tag24，全部payload恰为1字节，其中Merge 0为**51个**，Intersect 3为**33个**，其它三种模式未在当前资源出现。mode0后存在真实 Stroke（如`data-TimeStretch.pag`、`marker.pag`、`test2.pag`），不能为求快只做Fill；mode3所在直接组均无后续Stroke，但这不证明上游禁止 Stroke。`list/3.pag`的`15,15,24,20`证明必须递归收集子组路径；`list/11.pag`的`19,24,20,19`证明合并结果后的新路径仍按源序参与后续内容。该扫描只证实字段和相邻标签，不代表完整文件已经可播放。

实施顺序：先以原生 `StrokePath` 把 Merge=0 的所有先前路径按次序合成**一个**曲线路径并清除先前节点，保留 Conic/开放轮廓/Stroke/后续Trim 的路径身份；再以 Apple CoreGraphics 的 `CGPath` 非零填充布尔API作为其余四种模式的候选路径运算。当前Xcode27 SDK的`CGPath.h:400–416`及Swift接口确认macOS13/iOS16起可用，本机重叠矩形交集探针得到四角闭合路径和预期`(10,0,10,20)`范围；[Apple公开文档](https://developer.apple.com/documentation/coregraphics/cgpath/union%28_%3Ausing%3A%29)也列出四种返回`CGPath`的运算。这是系统几何构造，**不是**把原版C++作为编译或运行依赖，也不改变Metal直接显示。先前拟“从现有扫描线三角网格产出Boolean结果”的做法只能得到填充面积，无法保证后续Stroke/Trim可消费的单一路径，因此改为先验证CGPath运算与上游PathKit的退化/开放/Conic边界，再接通已证实类型；不能证明等价的输入仍明确失败。任何未接通模式在完整形状准备前明确失败，绝不按Merge=0替代。两段均要验证实际挂载drawable的重叠、孔洞、交集与Stroke像素；正式开放与资源分类、独立终核按架构完整功能边界执行。

后续源码细化：[libpag锁定的TGFX提交`062b864...`的`Path.cpp::addPath`](https://github.com/Tencent/tgfx/blob/062b864b1425de23fe5a63fbb67137974a4af215/src/core/Path.cpp#L490-L518)对Boolean直接调用PathKit `Op`，Append另走原路径追加；[Skia同源PathOps边界构造](https://github.com/google/skia/blob/main/src/pathops/SkOpEdgeBuilder.cpp#L93-L162)在普通布尔输入的开放轮廓末尾补闭合边。这支持开放路径在**填充布尔**时隐式闭合的推断，不意味着CoreGraphics和PathKit对全部退化或曲线输入逐点等价。当前Swift只让无Conic的有限Move/Line/Quad/Cubic进入CoreGraphics，返回元素转回可被本库Stroke/Trim消费的`StrokePath`；Conic因CoreGraphics缺有理二次指令仍明确`mergePathsConicBoolean`，同步系统调用前按输入规模二次收费并设上限。两个相交矩形的四模式、开放三角与矩形交集及交集后的Stroke边界已在**挂载macOS drawable**逐点核对；单一路径、前Paint清除、后Trim及预算/空结果另有纯语义测试。

真实资源增量探查：`list/3.pag`、`list/4.pag`、`list/5.pag`、`list/8.pag`、`moonlight.pag`、`transitions.pag`六份文件已完整载入，**718个源帧**均能生成帧计划，并在200×200单平台布局下全部通过生产Metal输入准备和附件回收；这不是正式demo实际窗口或三宿主验收。`list/7.pag`越过tag24后仍因独立`trackMatte`明确失败。首轮Metal遍历在`list/3.pag`根帧77发现静态Picture候选包住动态store采样几何而触发`metalPictureShapeIdentity`；已按[架构的静态身份合同](../架构设计.md)令**完整静态内容证书**下的几何ID使用`sampleFrame=nil`，保留未获证书者的源帧身份，随后718帧Metal重跑通过。Shape Picture相关38项/7组定向回归也通过。复杂曲线/Conic、切触与退化PathKit差异、正式真实文件窗口画面、完整库/126重审及独立终核仍未完成；不能把六份“输入准备通过”写成完整P7格式支持。

后续已挂载macOS drawable专项补充两个独立面积金值：外矩形减内矩形后，环带两侧不透明蓝、中央内孔及外部透明；闭合三次Bezier拱形与矩形交集后，拱顶外透明、拱形内部保持蓝色。`MetalMergePathsPixelTests`全组6项通过，覆盖Append、四种Boolean、开放三角、后续Stroke及这两个新边界。此证据只说明当前CoreGraphics→本库Metal在这些离边界取点上的结果，**不能**推导与锁定PathKit在切触、退化或有理Conic上全面等价。Conic Boolean仍明确失败，不因新增像素检查提前关闭MergePaths功能边界。

额外只读系统探针：两个仅共用一条边的CG矩形做`.intersection(using: .winding)`返回零元素空路径。此结果来自本机CoreGraphics，尚无锁定PathKit相切路径金值，不能据它修改源格式或将全部切触输入列为等价支持；正式边界仍需上游比较或明确门禁。
