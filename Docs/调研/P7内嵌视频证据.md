## 颜色、硬解与Metal所有权

`VideoSequenceDemuxer`指定BT601_LIMITED；iOS HardwareDecoder请求420v并把此矩阵传给图像输入，不能把系统输出默认颜色当成PAG语义。固定TGFX源码 `src/gpu/glsl/processors/GLSLTextureEffect.cpp::emitYUVTextureCode` 提供颜色数学：Y减16/255，UV减0.5；601矩阵列为 `(1.164384,1.164384,1.164384)`、`(0,-0.391762,2.017232)`、`(1.596027,-0.812968,0)`。alpha偏移区使用Y的 `(Y-16/255)/(218/255)` 并钳制到0...1；不是普通219分母，也不是读取色度推alpha。alphaStart为零时输出不透明。这里只引用数学，不移植OpenGL/CGL。

本机Swift6.4/macOS27硬解探针 `/tmp/PAGVideoProbe.swift` 使用macOS26目标实际编译并执行，输出 `/tmp/pag-video-probe-output.log`。52条序列各解前10帧，共520帧；要求硬件解码且属性返回true；所有工作均非主线程，输出均为420v，Y/UV以R8/RG8成功导入CVMetalTextureCache，没有调用CVPixelBufferLockBaseAddress或读回像素。

直接使用CMVideoFormatDescriptionCreateFromH264ParameterSets时，27份输出标601、25份标709，而输入描述中27份矩阵缺省、25份明确601，均为非full-range。保留avcC等全部扩展、明确601和非full-range后通过CMVideoFormatDescriptionCreate重建格式，重复520帧探针全部输出601，见 `/tmp/pag-video-probe-explicit-color.log`；其编译日志 `/tmp/pag-video-probe-build.log` 无警告。该实测是显式格式步骤的原因，不能只凭系统猜测标签通过颜色验收。

系统API合同依据当前SDK `VTDecompressionSession.h`：同步标志均关闭时，输出回调在DecodeFrame返回前完成；即便如此回调不直接访问actor字段。Apple的[解码说明](https://developer.apple.com/documentation/videotoolbox/vtdecompressionsessiondecodeframe(_:samplebuffer:flags:framerefcon:infoflagsout:))与[CoreVideo Metal导入说明](https://developer.apple.com/documentation/corevideo/cvmetaltexturecachecreatetexturefromimage)分别支持完成顺序及CVMetalTexture必须强保活到GPU完成的要求。`VTSession.h`的CopyProperty用void*输出且要求调用方release，Swift通过Unmanaged接收后takeRetainedValue，不把AnyObject?地址隐式当原始指针。

## 内部输入、取消与GPU数学检查点

源码入口：`Loading/PAGVideoDecoder.swift`、`Scene/SourceVideo.swift`、`Media/H264Format.swift`、`H264Session.swift`、`VideoSessionLifetime.swift`、`VideoFrameStore.swift`、`VideoFrameTransfer.swift`。本节记录内部输入检查点；当时公开Loader仍拒绝`fileTag:50`。后续共同绘制接通与公开开放见下一节。

`PAGVideoTests`完整读取52条真实序列；`PAGVideoBoundaryTests`覆盖截断、负alpha、零尺寸、SPS类型/边界、重复PTS、缺首关键帧、关键帧时间不符、重排深度、预算与预取消。`VideoToolboxInputTests`实际解码并导入520帧，要求硬件属性true、非主线程、420v、BT.601和PTS保持。`VideoFrameStoreTests`再按显示时间逐帧访问全部52条序列，共**9,073个压缩样本，每样本实际提交VT一次**，包括末端PTS空洞；另验收最近关键帧seek、同帧不重解、4条LRU、实际字节预算与旧帧保活。

## 同步Decode与Invalidate互斥修正

2026-10-01，Trim③完整回归在`VideoCancellationTests.cancellationDiscardsOutputBeforePublication`中终止。原日志`/tmp/pag-swift-p7-trim-display-full.log`未输出Swift Testing断言失败；系统报告`swiftpm-testing-helper-2026-10-01-035929.ips`指出FOUNDATION终止、`os_unfair_lock is corrupt`，故障线程55的`pag.video`栈为`vtRemoteDecoderFindAndRemoveFrameFromPendingFrameList → RemoteVideoDecoder_DecodeFrameWithOptions → VideoSessionLifetime.decode → H264Session.decode`。这是实际发生的系统解码/销毁重叠风险，不能因该用例随后单独重跑2项通过而忽略。

旧桥允许清理队列在同步Decode及输出回调尚未退出时Invalidate。当前macOS27 SDK `VideoToolbox/VTDecompressionSession.h`135–145行描述Invalidate有序销毁，166–174行保证不开asynchronous/temporal flags时Decode返回前完成回调；没有本实现所需的并行强制唤醒保证。先在架构取消合同中去掉该保证并说明等待边界，再修改生产桥：清理队列取得原有decode执行锁后才取走会话并Invalidate。取消回调仅立即关闭接纳并投递一次清理，不取执行锁、不等待系统；后台owner在失败/替换前继续排空清理，旧输出仍丢弃。

测试事件分为`.waitingForDecode`（清理开始但尚未取得执行锁）与`.invalidating`（Decode和回调已退出，即将调用系统销毁）。真实回调暂停时取消，等待前者并断言失效次数为0；释放回调后等待CancellationError，再断言仅失效一次、没有部分缓存且下一请求正常恢复。SDK外部调用停滞时不能保证即时物理中断，公开任务仍须等待在途同步系统调用返回；主线程保持可运行，不通过并行销毁规避这一限制。
