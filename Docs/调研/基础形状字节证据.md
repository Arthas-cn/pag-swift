# 基础形状字节证据：red.pag

这是 P1a/P1b 的只读格式调研；当前实现进度单独见 [格式支持矩阵](../格式支持矩阵.md)，不能仅用本文调研视为代码验收。参考源码为 `/Users/arthas/shibo/iOSProject/libpag`，HEAD `380e5cddcdacd3d15be785cb2e2dccd2f0c8f002`。以下源码路径相对该目录。

样例为本仓库 `resources/red.pag`，165 字节，SHA-256 `ec36c9b9ebcf2d7099f1592dce120eab31646f707c66bd67ada8902b6fe8b976`。本文的偏移均为文件起点计数、十进制、左闭右开 `[start,end)`；不是可以套给其他文件的固定布局。解析结果由只读 Python 探查按下列源码规则得到，所有子标签消费长度以及最终偏移都核对到边界；未运行上游画面作为截图基准。

## 读取基础规则

| 规则 | 源码依据 | 实现时必须保留的区别 |
| --- | --- | --- |
| 初始字节序为 little-endian | `src/codec/utils/DecodeStream.h::byteOrder` 的说明；其内部 DataView 构造默认相同 | UInt16、UInt32、Float32 均按小端读取；不能用主机未对齐指针直接加载不可信字节。 |
| 无符号编码整数是低 7 位组在先，第 8 位表示继续 | `DecodeStream.cpp::readEncodedUint32/readEncodedUint64` | 限制字节数、范围和输入边界；Swift 拒绝超界非终止编码时记录为更严格输入校验。 |
| 有符号编码整数最低位为符号，其余是绝对值 | `DecodeStream.cpp::readEncodedInt32/readEncodedInt64` | `value = encoded >> 1`，低位为 1 则取负；不是 ZigZag。 |
| 单位为 Frame 的时间读取无符号编码整数 | `src/codec/DataTypes.cpp::ReadTime` | 不得直接当作公开微秒；30 fps 下 450 帧才换算为 15,000,000 微秒。 |
| 字符串为以零终止的 UTF-8 | `DecodeStream.cpp::readUTF8String` | 终止符必须处于当前子流内，不是先读长度；缺终止符失败。 |
| 位流从每字节最低位开始，低位部分先并入结果 | `DecodeStream.cpp::readUBits` | LSB-first，不是网络协议常见的 MSB-first。 |
| 位和字节游标关联 | `DecodeStream.cpp::bitPositionChanged/positionChanged`；`DecodeStream.h::alignWithBytes` | 读位后字节位置向上取整；开始读取字节值时丢弃剩余 padding bits。不能每读一个 flag 就推进整字节。 |
| 一组属性先读全部 flags，再对齐，再读全部值 | `src/codec/AttributeHelper.h::ReadTagBlock` | “flag 后紧跟本字段值”是错误解释。 |
| 标签头读 UInt16：code=word>>6，length=word&63；length=63 时再读 UInt32 | `src/codec/TagHeader.cpp::ReadTagHeader` | 每个 payload 用独立边界子流；标签号来自 `include/pag/file.h::TagCode`。 |

### 属性 flags 与默认值

依据 `AttributeHelper.cpp::ReadAttributeFlag` 和 `AttributeHelper.h::{ReadValue,ReadProperty,ReadAttribute,CustomAttribute::readAttribute}`：

1. `FixedValue` 不读 flag，字段值总是存在。
2. `Value`、`BitFlag`、`Custom` 各读一个 exist bit。BitFlag 的 bit 本身就是布尔值，不再读取载荷，也不把 0 改成配置中的默认 true。
3. 普通 Property 先读 exist。exist=0 时直接创建默认常量，不读 animatable。
4. exist=1 的 Property 再读 animatable。仅 SpatialProperty 且 animatable=1 时额外读 hasSpatial。
5. 默认常量也必须在结果里存在，不能因为字段没字节就遗漏整个属性。red 的 fill 恰好完全依赖默认值。
6. `Custom` 为真才调用自定义读取器；ShapeGroup 的 custom 部分是嵌套 shape tags，并以 End 终止。

red 的全部 Property 均为静态常量。遇到 animatable=1 不可继续按常量读取：应转入完整关键帧读取器或明确 unsupported。本报告只给最小静态闭包，不声称支持所有动画属性。

入口依据：`FileTags.cpp::ReadTagsOfFile` → `VectorCompositionTag.cpp::ReadVectorComposition/ReadTagsOfVectorComposition` → `LayerTag.cpp::ReadLayer/ReadTagsOfLayer` → `ShapeTag.cpp::ReadShape` → `shapes/ShapeGroup.cpp::ShapeGroupTag/ReadShapeGroupElements`。

文件头 `[0,9)` 依据 `Codec.cpp::ReadBodyBytes`：magic `[0,3)` 为 `PAG`，version `[3,4)` 为 1，bodyLength `[4,8)` 为 156，compression `[8,9)` 为 `U`（0x55）。不是 compression=0。bodyLength 与实际剩余长度完全相等。当前上游 KnownVersion=3、EncryptedVersion=3，但 version=3 会先走加密失败，不能按 `<= KnownVersion` 一概成功。

FileAttributes 依据 `tags/FileAttributes.cpp::ReadFileAttributes` 顺序读取：timestamp 编码 Int64 为 69870310941；pluginVersion=`2.1.38`；aeVersion=`17.0.1x52`；systemVersion=`Mac10.15.5`；author 为样例内字符串；scene=`VideoEdit`；warningCount=0。这里没有画面状态。若 P1a 不向外公开这些字段，也须按标签边界合法消费/明确允许忽略，而不是把它当 root composition。

## 合成与图层

`VectorCompositionTag.cpp::ReadVectorComposition` 先读编码 UInt32；red `[72,75)` 为 ID 20010。`CompositionAttributes.cpp::ReadCompositionAttributes` 无属性 flags，其固定字段顺序如下：

| 范围 | 读取方式 | 字段与预期 |
| --- | --- | --- |
| `[77,79)` | encoded Int32 | width=720 |
| `[79,81)` | encoded Int32 | height=1280 |
| `[81,83)` | ReadTime / encoded UInt64 | duration=450 帧 |
| `[83,87)` | Float32 | frameRate=30 |
| `[87,90)` | 三个 UInt8，依次 red/green/blue | backgroundColor=(0,0,0)；这只是元数据，不由此推断默认屏幕 clear color。 |

`LayerTag.cpp::ReadLayer` 先读 UInt8 layerType，再编码 UInt32 ID：`[96,97)` 为 4（`include/pag/types.h::LayerType::Shape`），`[97,100)` 为 20013。根有一个形状图层。`File.cpp::File` 用 compositions.back() 作 mainComposition，`PreComposeLayer.cpp::Wrap` 创建运行时 root layer；不能凭字节臆造 root layer 的另一个 ID。

LayerAttributesV2 配置来自 `tags/LayerAttributes.cpp::MakeFromLayerAttributesTag`。下面 bit 编号相对 payload 起点 102，LSB-first；flags 是 `01 01` 两字节，读取到 bit 9 后对齐至偏移 104。

| 字段顺序 | 属性种类 / bit | red 值 | 默认来源 |
| --- | --- | --- | --- |
| isActive | BitFlag / 0=1 | true | bit 直接为值 |
| autoOrientation | BitFlag / 1=0 | false | bit 直接为值 |
| parent | Value / 2=0 | nil | Layer* nullptr |
| stretch | Value / 3=0 | numerator=1, denominator=1 | `file.h::DefaultRatio` |
| startTime | Value / 4=0 | 0 帧 | `types.h::ZeroFrame` |
| blendMode | Value / 5=0 | Normal=0 | `types.h::BlendMode` |
| trackMatteType | Value / 6=0 | None | LayerAttributes 配置 |
| timeRemap | SimpleProperty / 7=0 | 常量 0 | LayerAttributes 配置 |
| duration | FixedValue / 无 bit | `[104,106)` ReadTime=450 帧 | 始终从载荷读取 |
| name | Value / 8=1 | `[106,120)` UTF-8=`Shape Layer 1` | 无值时空字符串 |

这里“timeRemap 属性默认 0”是解码事实，不等于求值时无条件把 layer time 变成 0；必须以运行时时间映射逻辑解释它的适用条件。

## Layer Transform2D

配置来自 `tags/Transform2D.cpp::Transform2DTag`，payload 第一个字节 `[122,123)` 为 `02`，以下 bit 编号相对偏移 122：

| 字段顺序 | 类型 / flags | 值 |
| --- | --- | --- |
| anchorPoint | SpatialProperty / bit0 exist=0 | (0,0) |
| position | SpatialProperty / bit1 exist=1、bit2 animatable=0 | `[123,131)` 两个 Float32=(360,640) |
| xPosition | SimpleProperty / bit3 exist=0 | 0 |
| yPosition | SimpleProperty / bit4 exist=0 | 0 |
| scale | MultiDimensionProperty / bit5 exist=0 | (1,1) |
| rotation | SimpleProperty / bit6 exist=0 | 0 度 |
| opacity | SimpleProperty / bit7 exist=0 | Opaque=255 |

Point 常量是两个 Float32（`Attributes.h::AttributeConfig<Point>::readValue` → `DataTypes.cpp::ReadPoint`），不是压缩空间列表。只有动画 SpatialProperty 的 value list 才涉及 `readFloatList` 压缩路径。

`LayerTag.cpp::ReadTagsOfLayer` 在读 Transform2D 后根据 combined position 与 separate x/y 是否非默认/动画决定保留哪一种表示。red position 非零，保留 combined position，删除 separate x/y。内部 Swift 可选用自己的枚举表达该结果，不需复制删除指针行为。

## ShapeGroup、Rectangle 与 Fill

ShapeGroup 配置来自 `tags/shapes/ShapeGroup.cpp::ShapeGroupTag`，flag bytes `[133,135)` 为 `08 02`，bit 相对偏移 133：

| 字段顺序 | 属性类型 / flags | red 值 |
| --- | --- | --- |
| blendMode | Value / bit0=0 | Normal |
| anchorPoint | SpatialProperty / bit1=0 | (0,0) |
| position | SpatialProperty / bit2=0 | (0,0) |
| scale | MultiDimensionProperty / bit3 exist=1、bit4 animatable=0 | `[135,143)` Float32=(0.4798107445240021,4.25517463684082) |
| skew | SimpleProperty / bit5=0 | 0 |
| skewAxis | SimpleProperty / bit6=0 | 0 |
| rotation | SimpleProperty / bit7=0 | 0 |
| opacity | SimpleProperty / bit8=0 | 255 |
| elements | Custom / bit9=1 | `[143,159)` 嵌套 Rectangle、Fill、End |

Rectangle 配置来自 `tags/shapes/Rectangle.cpp::RectangleTag`；flag byte `[145,146)` 为 `02`，bit 相对偏移 145：

| 字段顺序 | 属性类型 / flags | red 值（缺省值） |
| --- | --- | --- |
| reversed | BitFlag / bit0=0 | false |
| size | MultiDimensionProperty / bit1 exist=1、bit2 animatable=0 | `[146,154)` Float32=(1500,300)；未存在时为 (100,100) |
| position | SpatialProperty / bit3=0 | (0,0) |
| roundness | SimpleProperty / bit4=0 | 0 |

Fill 配置来自 `tags/shapes/Fill.cpp::FillTag`。payload 只有 `[156,157)` 一个 `00`。依序 blendMode、composite、fillRule、color、opacity 的 exist bits 全为 0，结果必须是：

- blendMode=Normal=0（`types.h::BlendMode`）。
- composite=BelowPreviousInSameGroup=0（`file.h::CompositeOrder`）。
- fillRule=NonZeroWinding=0（`file.h::FillRule`）。
- color=Red=(255,0,0)（`types.h::Red`），静态常量，不存在额外 RGB 字节。
- opacity=Opaque=255（`types.h::Opaque`），不读取额外 alpha 字节。

仅看到全部 flags 为零就把 Fill 视为缺失，会丢失 red 的唯一颜色。也不能仅支持 SolidColor tag 就把此 ShapeLayer 当作纯色层；几何和 group transform 都决定画面。

## 从解析结果到几何的可验证预期

源码依据 `src/rendering/renderers/ShapeRenderer.cpp::{RectangleToPath,ShapeTransformToTransform,RenderElements_ShapeGroup,FillToPaint}` 以及 `TransformRenderer.cpp::RenderTransform`：

- 矩形以 position 为中心，范围先是 x=-750...750、y=-150...150，roundness=0。
- group transform 的顺序为移除 anchor → scale → 可选 skew → rotation → position。red 只施加非均匀 scale。
- layer transform 只把它平移到 (360,640)。因此由数值运算推得几何宽约 719.716116786，高约 1276.552391052，中心 (360,640)；不是应强行修正成恰好 720×1280。抗锯齿后的边缘像素需后续 Metal 实测，本文不承诺逐像素结果。
- red 没有关键帧、视频、位图、文本、蒙版、效果、父控制层或预合成引用。0、任意中间有效时刻和 progress=1 应求值到同一个静态形状内容；自然播放仍有 15 秒时间轴。
- 本例的已解析元数据：composition 720×1280、30 fps、450 帧、15,000,000 微秒；一个 ShapeLayer，start=0、duration=450、visible=true；editable texts/images/videos 均为 0。

## 完整验证与未覆盖边界

即使这个样例很小，仍需走 `Codec.cpp::Decode` 的引用安装与 VerifyAndMake 门槛。验证依据包括：`Composition.cpp::verify` 的正尺寸/时长/帧率；`VectorComposition.cpp::verify` 遍历图层；`Layer.cpp::verify` 的 containingComposition、正时长、可用 transform；`Transform2D.cpp::verify` 的完整属性；`ShapeLayer.cpp::verify`、`shapes/ShapeGroupElement.cpp::verify`、`ShapeTransform.cpp::verify`、`RectangleElement.cpp::verify`、`FillElement.cpp::verify` 的必要子对象检查。Swift 应进一步拒绝非有限 Float、无界节点/字节预算，不以源代码只检查非空为足够安全。

P1a/P1b 可用真实 red 测试以上数值和层树，对截断、越界、错误 flags 组合使用明确标成损坏输入的变体。不要手造一段“合法 PAG”代替真实夹具。每个标签必须在限定子流内消费；不完整 End、长度或必要内容失败，不得返回可播放文档。

未由 red 验证的内容包括关键帧/Hold/Bezier/spatial easing、一般 shape path、椭圆、渐变、描边、路径运算、复杂混合、蒙版、3D、timeRemap、stretch、bitmap/video/text。上游读取入口有证据不等于 Swift 已实现；涉及它们的输入应明确 unsupported，直到独立证据闭包和真实样例验收完成。red 的 Fill/Rectangle 子集也不能成为跳过未知必要 shape tag 的理由。
