# P7 Track Matte 源码与真实字段证据

只读上游 libpag 固定于本仓库既定版本。`include/pag/file.h:1719–1725`定义`TrackMatteType`为`None=0`、`Alpha=1`、`AlphaInverted=2`、`Luma=3`、`LumaInverted=4`。`src/codec/tags/LayerAttributes.cpp::MakeFromLayerAttributesTag`在非Camera层的blend字段后、timeRemap前，以`Value<UInt8>`保存该枚举，缺省None；V3在前面另插入motionBlur位标记，不改变本字段的值宽度。未知值不能猜成Alpha或None。

`src/codec/Codec.cpp::InstallReferences(const std::vector<Layer*>&)`按同一Vector合成的**编码层顺序**安装引用：当前层序号大于0且类型属于四种有效遮罩时，将`trackMatteLayer`设为`layers[index−1]`，并非按层ID查找。序号0即使记录非None也没有引用；上游`TrackMatteRenderer::Make`在引用为空时返回空。普通合成绘制见`CompositionRenderer.cpp::RenderVectorComposition`：按编码层逆序遍历，只有正常绘制时才检查层的`isActive`；遮罩内容则由`TrackMatteRenderer.cpp::Make`另行调用`LayerRenderer::DrawLayer`，故不能把inactive的遮罩源层直接丢弃。遮罩源使用同一所属合成帧，独立减自身`startTime`取内容帧，并应用它自己的变换、透明度、filter与mask。

`TrackMatteRenderer.cpp::MakeMaskModifier`把1/2映射为alpha、3/4映射为luma，2/4再反向。`LayerRenderer.cpp::DrawLayer`的次序是外层alpha/blend、track matte、extra/layer transform、filter、源层普通/羽化mask、内容；文本遮罩中彩色字形还有单独叠加边界。`Modifier.cpp::MakeMask`在非luma且图形能直接给出Path时可降为clip；一般遮罩只在受交范围内借**局部**内容和mask surface，luma使用`0.2126 R + 0.7152 G + 0.0722 B`色彩矩阵，反向由mask filter执行。引用存在而源图形为空时，非反向会遮空，反向不安装约束。Swift终态须维持根Metal pass直写drawable，按需局部附件不得演变为每帧整屏拷贝或CPU读回。

后续逐分支核对发现“无引用”和“引用有、图形空”必须分开：`TrackMatteRenderer::Make`在首层无`trackMatteLayer`时直接返回nullptr，`CompositionRenderer`把null传给`LayerRenderer::DrawLayer`，拥有者不安装轨道遮罩；只有引用存在且`DrawLayer`因源时间区间/透明度等产出空Graphic时，`Modifier::MakeMask(nullptr, inverted, useLuma)`才产生正向空遮罩或反向无约束。旧证据段的“无mask”只指后一种空图形，不能扩展到首层无引用。已先修架构合同，求值需要分别测试。

变换时钟已按完整调用链确认：`LayerRenderer.cpp::DrawLayer`将所属合成帧减`startTime`以查询缓存；`FrameCache.h::getCache`在调用`TransformCache.cpp::createCache`前加回该层起点，因此`RenderTransform`对自身及控制父层均使用所属合成帧。此前仅看前后两层而怀疑当前Swift `LayerTransformSampler`的合成帧采样有冲突，是漏看`FrameCache`的误判；现已在架构修正，不需要改共享时钟。非零起点仍宜有定向回归，静态范围缓存只能复用等价值。

`TrackMatteSampling`现按同合成已验证拓扑返回unmasked、保留模式的empty或源索引/局部内容时间/合成帧变换三种结果；首层非None与有引用但源时段外经语义测试明确分开，inactive源仍可选。零alpha/奇异源矩阵按`LayerCache::contentVisible`分流为空，控制父自身透明度不传给源层。它尚不准备滤镜、mask或图元，不能作为Metal可见结果。

初始检查点只建立字段和调用次序证据；当时`PAGLayerDecoder.readLayerAttributes`在trackMatte非默认值上明确失败，`SourceLayer`及FramePlan尚无track matte对象。后续先用已取证的文件/层标签边界统计真实模式与相邻源层，再按架构分段实现解码、引用、采样、局部Metal及可见验收。原有126分类的trackMatte失败行是**旧审计**，不能凭本证据升级为支持。

真实字段调查以`PAG_TRACK_MATTE_AUDIT=1 swift test --filter PAGTrackMatteEvidenceTests`沿文件头、Vector合成、Layer及属性标签边界读取全部126份资源。调查首次误把tag7的Transform当成LayerAttributesV2，导致`DropShadow.pag`短子流越界；已按`include/pag/file.h`的实际编号修正为**6/52/62**，Camera层按上游配置跳过blend和track matte槽。最终发现**41个非零字段**：Alpha=36、AlphaInverted=4、Luma=1、LumaInverted=0；所有值均落在0...4。`repeater.pag`合成684的层696位于编码索引0、记录Alpha=1，但按`Codec::InstallReferences`不会安装遮罩引用，不能把“非零字段”直接等同“有遮罩”。`PAG_LOGO.pag`的合成161层1860记录唯一真实Luma=3；`list/7.pag`合成2层4记录Alpha=1。上述只证明字段及相邻关系，未验证实际遮罩画面。

调查器后续沿同一合成的编码顺序保存上一层ID与类型，40个实际引用的源层类型分布：Shape(4)=32、Precomposition(6)=3、Solid(2)=2、Text(3)=2、Image(5)=1；另1个首层无源。文件证据说明仅为Solid做一条特化渲染无法覆盖P7主体，必须让已有Shape/Text/图片/预合成内容准备进入通用局部遮罩。首层无源则按上游返回null modifier，可独立验证并开放，不必等待有引用的GPU效果。

首层分支在Vector`readComposition`按编码数组长度判断，非首层非None仍明确拒绝；`FramePlanner`也以`TrackMatteSampling`阻止手工语义图绕过门禁。首层Alpha的语义场景经正式帧计划和已挂载macOS drawable读到原红色RGBA；`list/7.pag`仍在trackMatte门禁。在这一子段，真实`repeater.pag`跨过首层字段后到达独立`layerTag:26`门禁，因此当时不能把语义场景像素冒充其画面；tag26后续完成情况见[Repeater证据](P7重复器证据.md)。Track Matte有引用源的通用效果仍须单独实现。

空源分支继续核对`src/rendering/graphics/Modifier.cpp::Modifier::MakeMask`及`MaskModifier::applyToGraphic`：`graphic == nullptr`且反向时返回`nullptr`，无额外约束；正向返回持空mask的`MaskModifier`，绘制直接结束。`FramePlanner`只把已判定`.empty`的正向模式跳过、反向模式直画；实际有源图形的`.source`仍明确失败。语义帧计划覆盖Alpha/Luma四模式，已挂载macOS drawable覆盖Alpha正反向实际透明/蓝色像素；这不等于有引用真实文件已可播放。

字段内部读取子段已将0...4定义为严格`SourceTrackMatteType`；`PAGLayerDecoder.readLayerAttributes`从真实属性子流解析，未知5按`unknownTrackMatteType`非法文件失败，而`readLayer`仍在发布前对非None抛原有`unsupportedFeature("trackMatte")`。真实Alpha、AlphaInverted、Luma及从真实Alpha载荷变换出的LumaInverted/非法5各有测试，真实载荷在模式字节前截断按偏移失败，另用`repeater.pag`锁定公开Loader仍失败。层时间属性与此调查合并定向**10项/2组通过**。此内部接线尚未保存到`SourceLayer`，不解析相邻引用、不产生可见遮罩或改变旧126分类；decoderRevision仍18。正式开放必须先完成剩余求值与Metal，并在完整功能边界集中复核。

2026-10-21双输入实现边界：`FramePlanner`在公开逆编码实例序中，把拥有者及紧邻的前驱源放入临时显式栈，发出`beginTrackMatte/endTrackMatteSource/endTrackMatte`三标记；源层即使inactive仍按自身局部时间、变换、透明度和内容求值，预合成源继续沿原实例栈展开。`MetalTrackMattePreparation`按真实两段图形范围借有界内容/源附件，正向只取交集、反向取拥有者范围；两个局部批次完成后最终根draw依alpha或上游亮度矩阵取源因子。祖先普通mask在这个最终draw才消费一次，修复了真实`list/7.pag`第120帧的初次`nestedTrackMatte`误拒。实际轨道遮罩自身嵌套及羽化内双输入仍明确失败；不能把`travel.pag`的独立`nestedMaskPaths`说成已支持。

合成Alpha/Luma四模式、源几何空但时间可见、Shape填充、inactive预合成源均到已挂载macOS drawable核对像素；真实`list/7.pag`全部源帧计划/Metal准备、逐帧附件归零，第120帧100×100挂载drawable含透明角和固定蓝色点RGBA约(62,190,235,255)，容差3。公开Loader解除总门禁并把decoderRevision升20；126份真实资源审计82通过/44明确unsupported，较上次新增10通过，详见[全资源分类](P7全资源分类.md)，日志`/private/tmp/pag-swift-track-resource-audit.log`。完整库1351项/246组通过；此前一次全库并行运行中`transferWaitsForCompletedOwnerToExit`触发60秒超时，单测0.064秒通过且随后全库14.958秒全过。没有正式Demo整帧窗口画面、最低系统26真机本子范围复验或独立终核，P7不标完成。

后续源模型子段把原始模式加入`SourceLayer`，包括编码索引0的非None值；`SceneValidator`按同一合成编码索引建立`CompositionTopology.trackMatteSources`，前一层inactive或ID无序都不改变所选源，预合成边界不跨越。新增拓扑数组在分配前计入解码预算。语义邻层和场景图定向**14项/2组通过**，真实字段与公开门禁单独**4项/1组通过**；后者仍拒绝真实非None层，所以尚未用完整PAG构造轨道遮罩画面。FramePlan、Metal和正式可见验收待续，分类和decoderRevision不变。
