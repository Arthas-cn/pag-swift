# P6 宿主验证（已通过）

日期：2026-09-29。前置P5已通过。本记录区分实现、自动测试、实际可见验证；**P6通过，可以进入P7**。当前运行系统为27，部署26和SDK可用性检查不替代最低系统的最终运行验收。

## 实际实现

- `Views/PAGView.swift`、`PAGUIView.swift`、`PAGNSView.swift`提供三种正式公开入口。SwiftUI只按平台包裹原生库View，不拥有另一份播放时钟。
- `Display/DisplayHost.swift`在MainActor协调一个实际操作与一个最新配置。布局变化先同步撤销旧显示代数，再取消并排空旧事务；相同输入不重复绑定。零布局不申请像素，离窗拆层，重挂保留播放器位置和意图。
- `DisplayHostToken`是可撤销的Sendable身份。PAGPlayer分别记录最新请求与已经绑定的宿主；旧宿主退出、失败或迟到完成不能污染新宿主/独立surface。测试覆盖新请求尚在配置等待中的交接。
- UIKit使用`UIUpdateLink(view:)`，暂停连续刷新后仍被动观察UI更新与祖先隐藏；AppKit使用`NSView.displayLink`及窗口/祖先/倍率通知。AppKit由自身管理backing layer，普通子父层隔离非零bounds原点。
- 静态首帧遇到临时drawable不可用时，ready/paused也会请求真实刷新恢复；成功后结束额外刷新，不推进暂停时间。没有sleep播放循环。
- 现有Metal后台owner直接向drawable绘制；没有新增离屏出图API、整屏中间复制、播放像素CPU读回、依赖或unchecked Sendable。
- iOS的Xcode运行发现后台层属性修改产生未提交隐式CATransaction警告。按SDK的CATransaction.h证据先修架构，再为后台device/像素格式配置与drawableSize修改加入同线程显式事务；获取drawable前已commit，不跨await或GPU等待。主机与两平台demo开启`CA_ASSERT_MAIN_THREAD_TRANSACTIONS=1`后通过，原警告未再出现。

SDK证据与平台刷新选择先写入[架构6.1.2](../架构设计.md)。本阶段没有新增PAG字节格式或扩大支持矩阵。

## Demo接入

`app/pag-swift-demo`使用同一不可变PAGComposition，分别安装到两个库PAGPlayer，展示SwiftUI和本平台原生入口。两个播放器是为了避免争用同一个surface，不实现额外播放逻辑。控制包含载入样例、播放、暂停、回到开头、0...1定位、缩放、尺寸变化、移除/重挂和原生祖先隐藏。

工程核对结果：

- library product为`pag-swift`，模块为`pag_swift`；实际App target的`packageProductDependencies`与`Frameworks`均引用该product。
- 新增显式`XCLocalSwiftPackageReference`，路径`../../packages/pag-swift`；移除旧绝对文件引用路径。文件系统同步目录只含demo，不把库源码直接编进App。
- target为`SWIFT_VERSION = 6.4`，Xcode实际`EFFECTIVE_SWIFT_VERSION = 6`；iOS/macOS部署26.0，Approachable Concurrency开启。demo默认MainActor，库默认仍是nonisolated。
- App target的平台限于iOS、iOS Simulator、macOS；去掉模板中无关的visionOS目标配置。
- 样例通过Copy Files复制到`PAGSamples/resources`。本机证据：当iOS App根部存在`resources`目录，`Bundle(url:).infoDictionary`为空且simctl安装报Missing bundle ID；同一产物只将该目录改名，Bundle ID即可正常读取。新复制位置重建后安装成功。仓库原`resources/`未移动。

## 已完成的实际可见验证

使用真实macOS App runloop的临时程序，公开PAGNSView与NSHostingView(PAGView)显示同一red.pag，屏幕上两者红色实底一致。程序实际得到occlusion位8194（包含visible位2），并记录：

| 操作 | 实际结果 |
| --- | --- |
| 两个入口静态首帧 | presentedTime非nil，红色内容实际可见 |
| AppKit原生View隐藏 | suspended |
| 隐藏期间主动pause，再显示 | paused，未擅自恢复播放 |
| 尺寸归零 | 显式render返回targetUnavailable |
| 恢复尺寸、bounds原点改为(10,15) | submitted，位置正确 |
| 从窗口移除 | targetUnavailable |
| 加回同一窗口 | submitted，继续使用原player |

随后正式macOS demo实际显示srgb.pag：SwiftUI/AppKit首帧均0μs且画面一致；点击播放后二者均推进；只隐藏原生祖先后AppKit为suspended，SwiftUI继续playing；隐藏时暂停、恢复祖先后仍paused；回到开头后均0μs；移除/重挂并缩小后仍paused；50%定位后二者均提交2520000μs。修正资源复制路径后重启正式demo，两个入口仍能载入并提交首帧。

早期尝试在SwiftPM辅助进程中等待AppKit可见首帧超时。诊断显示该进程窗口isVisible为true但occlusion为8192，不含visible位2；正式App环境验证通过。因此库测试改为检查未呈现窗口的绑定/布局/祖先事件/拆除，可见画面留给上述真实GUI验收。没有关闭生产遮挡检查，也没有把超时测试改为无条件成功。

## Xcode工程最终运行验收

Device Hub界面读取持续超时，用户明确允许改从Xcode工程运行验收。最终使用`Product > Destination`分别选择同一iPhone Air和My Mac，`pag-swift-demo` scheme执行Run。两个平台都实际报告Running；没有把该状态本身当成验收结果。

`DemoHostVerification.swift`通过显式启动参数`--verify-pag-hosts`运行有限的真实宿主流程。两个平台的Xcode控制台均依次报告以下7项PASS：

1. 两个宿主首帧有效提交。
2. 系统刷新使实际presentedTime向前推进。
3. 原生祖先hidden使对应播放器suspended，另一个SwiftUI播放器仍playing。
4. 隐藏期间主动pause，恢复后保持paused，两个入口均提交1000000μs。
5. 两个真实View高度归零后suspended，恢复正尺寸后playing。
6. 从SwiftUI树移除再重挂，两个原播放器保持播放意图并恢复playing。
7. 两个入口最终均paused，提交时间相同且为2000000μs。

等待使用快照事件；15秒只是失败上限，不用sleep猜UI时序。流程没有替代时钟、像素读回或新播放器。结束后恢复手动布局控制。参数及CA事务断言已保留在共享scheme中，默认均关闭；复核时在Edit Scheme > Run > Arguments启用这两项，然后Run默认srgb样例。

iOS通过Xcode Debug View Hierarchy实际捕获了首帧和最终2000000μs画面，SwiftUI/UIKit内容一致；macOS实际窗口显示“宿主验收通过（7项）”，SwiftUI/AppKit也均为paused、2000000μs，蓝色内容及内部图形与iOS捕获吻合。这是可见画面核对，不是上游逐像素差分。Xcode捕获属于调试工具，不是库的播放读回或导出API。

运行时还出现系统的app launch measurement/autoShortcut连接日志，未见库failed状态或CA事务断言失败；这些日志不能被混作本库绘制错误。
