# P7 描边性能验收

## 状态与方法

2026-09-30：普通Stroke的④a/b/c闭包已通过，tag21开放、decoderRevision11；最新数值修复后的成本见文末。以下保留先性能、再drawable及三宿主的测量历程，都是本机观测，不是跨设备FPS保证，也不代表完整P7通过。

环境：Apple M5、Mac17,2、32GiB内存，macOS27.0（26A428），Xcode27/Swift6.4。显式启用`StrokePlaybackBenchmarkTests`，在`packages/pag-swift`执行`PAG_STROKE_BENCHMARK=1 swift test -c release --filter StrokePlaybackBenchmarkTests`，配合已有`--disable-sandbox`和`/tmp`模块缓存。Release的dSYM生成被沙盒拒绝后，在沙盒外运行同一测试，最终3项/1组通过；编译54.23秒，探针1.188秒。日志`/tmp/pag-swift-p7-stroke-cost-release.log`。

冷路径从`RenderGeometryCache.mesh`前开始，包含中心线、dash、outline、折线与nonzero网格；输入夹具构造、源载荷读取和编译不计入。成功后独立测16次同对象同精度warm命中，要求每次只消耗1 work。颜色32帧只计prepare；宽度动画8帧计prepare+mesh。逻辑64MiB/work16,777,216沿原限额不变。

`getrusage(RUSAGE_SELF).ru_maxrss`按本机Darwin手册以字节报告整个测试进程累计峰值：它包括测试运行时和之前场景的驻留，不是当前调用净分配，不能拿来证明64MiB逻辑预算等于RSS。取消探针在工作线程预算/缓存准备就绪5ms后cancel并等待，报告实际work；只有结果为cancelled才将耗时解释为取消响应。独立复核已修正非资源PAG错误被吞和信号先于可取消初始化的问题。

## 结论与下一步合同

颜色帧的逐点校验已得到本机成本数据，当前不为这一约0.06ms中位开销增加额外缓存或验证状态。冷几何的二次边对扫描和每带重扫历史边仍不合格：warm极快不能抵消约300ms首次准备或约400ms后才拒绝的输入。不得据此宣称所有默认接纳几何可实时逐帧重建。

先按`Docs/架构设计.md`④c新增的有界投影候选与活动边游标合同复核，再改共享剖分器；保留原交点计算顺序、填充语义、精度与预算。改后使用同一探针重测并记录剩余风险。性能门禁尚未通过；实际drawable、三宿主及正式tag21门禁均未提前通过。

决定：当前优化消除了常见分离图元的无效二次扫描，保留现有预算，继续④c的实际drawable验收。大输入冷准备仍需22–31ms，密集交叉约125ms后拒绝；不承诺这些输入每帧都能在16.7ms内重建。颜色/静态几何命中、可协作取消和明确资源失败是当前播放优先策略；真实完整文件重新分类、GPU资源上传/提交和三宿主仍需后续验收，不能以本节CPU数据替代。

独立终核已确认密集交叉夹具与统计口径有效，成本材料足以进入drawable检查点，无剩余必须修复项。该样本不是绝对最坏耗时上界；实际GPU、真机和三宿主仍待验收。
