# P5 覆盖接入验收（阶段内检查点）

日期：2026-09-28。接续[覆盖计算验证](P5覆盖计算验证.md)，将已经验证的面积计算接入实际Metal显示路径。**P5仍未通过**；本记录证明生产接入、数值/资源/生命周期回归和本机性能，不替代屏幕画面、最终色彩、公开播放器或三个宿主验收。

## 实际接入

`MetalResources.mesh`在网格首次上传时建立BVH，同时保留顶点、节点、三角形索引三个不可变buffer。它们共用网格身份、LRU条目和当前帧保活；跨帧命中不重建索引。分配前预留最坏索引成本，创建后按三个buffer实际allocatedSize补足；命中也检查完整成本。单帧裁剪buffer按`max(length, allocatedSize) + 512`计费，修正了实际分配较大时元数据可能漏计的问题。

`MetalFramePreparation`将作用域中的真实矩形求为完整凸交集，再按边数组值共享一段单帧输入。没有额外裁剪使用零边数；真实空交集直接跳过图元，不能变成无裁剪绘制。每个完整填充只产生一次向外扩展的整数像素包围矩形，保证分数像素边缘也有候选片元。它不是填充轮廓或真实裁剪，真实覆盖仍来自图元、凸区域、像素三者求交。

`MetalDrawTransform`先在Double中补偿源原点，再固定实际上传的Float正向矩阵，由这份矩阵求逆和包围范围。若Double可逆而Float已退化，明确返回renderingFailure；超出Float表示范围同样失败。该边界已先写进架构，避免GPU使用的顶点与BVH查询逆矩阵不一致。

`MetalDrawUniforms`现在为112字节，包括正向行、预乘色、裁剪范围/节点数、pass原点、逆矩阵和包围矩形NDC。`MetalFrameBatch`每个绘制只提交六个包围矩形顶点，绑定单帧裁剪buffer与缓存的三个网格buffer。`MetalShaders`中的纯色与图片入口调用同一`pagMeshArea`，同一填充内全部候选三角形面积相加后仅做一次SrcOver。图片与局部组纹理使用相同逆矩阵恢复UV，预乘颜色仅乘一次联合覆盖。

最终pass继续直接使用drawable.texture；普通内容没有固定整屏中间附件、MSAA resolve、blit或CPU画面读回。整体透明度仍只使用此前实现的必要局部附件，完成后归还。没有公开离屏出图接口、新依赖或新增PAG字节规则。

## 验证

完整库`swift test`报告**344项、54组、无失败**；沙箱中17项GPU用例和1项显式启用的性能探针跳过。随后同一debug测试产物以主机权限、Metal API Validation运行以下6组，**17项全部实际通过**：

- MetalCoverageMathTests：保留5,670个三角形/裁剪样本与2,048个真实字形网格样本的独立Double参照，已测误差小于1e-4。
- MetalCoveragePreparationTests：重复裁剪共享、分数像素候选边缘、旋转裁剪AABB相交但凸交集为空、三个输入buffer跨帧复用、缓存命中预算和实际裁剪分配成本。
- MetalResourcesTests：新MSL实际编译，真实TEXT04的完整fill/stroke轮次、裁剪范围和局部组准备。
- MetalGroupTests：组alpha、嵌套pass与裁剪恢复、失败归还、池预算/身份。
- MetalDrawableIntegrationTests：真实窗口提交red、TEXT04、ImageDecodeTest及两级透明组；编码后撤销、resize重提、旧代数拒绝与inactive目标回归。此次实际调用新覆盖片元路径。
- DisplayTargetIntegrationTests：专用执行器、配置/取消、等待租约和关闭。

新增纯CPU用例还验证GPU变换系数与逆矩阵的一致性、Float退化与变换后溢出；原点补偿、共享布局偏移、局部pass映射测试已同步。输入buffer检查只读取CPU准备的输入；GPU数值测试只检查覆盖标量，不读取最终帧颜色。

全部**92个库源码**通过iOS26目标、Swift6严格并发、ApproachableConcurrency、warnings-as-errors实际`swiftc -c -whole-module-optimization`编译。产物为2,473,928字节；这不是iOS GPU运行或三宿主验收。

复现普通库测试：

```sh
CLANG_MODULE_CACHE_PATH=/tmp/pag-swift-clang-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/tmp/pag-swift-module-cache \
swift test --disable-sandbox --cache-path /tmp/pag-swift-spm-cache
```

宿主GPU回归使用同一命令加`MTL_DEBUG_LAYER=1`、`--skip-build`和上述测试组过滤。

## 有界播放性能探针

新增显式启用的`MetalPlaybackBenchmarkTests`，只创建一个真实NSWindow和一个1280×720 drawable目标，顺序测量四个场景，结束后关闭窗口。每场景预热4帧，再连续提交32帧。测试使用P5实际RenderOwner链路，提交静态零时刻来隔离覆盖/编码成本，不声称测量了所有动画关键帧。

RenderOwner内部诊断只传请求ID与GPU秒数。时间戳在真实完成回调读取，依据当前SDK的`MTLCommandBuffer.h::GPUStartTime/GPUEndTime`；对应Apple公开入口为[gpuStartTime](https://developer.apple.com/documentation/metal/mtlcommandbuffer/gpustarttime)与[gpuEndTime](https://developer.apple.com/documentation/metal/mtlcommandbuffer/gpuendtime)。它们不参与播放状态判定，不改变迟到丢弃规则，不跨域传裸command buffer。

本机Apple M5、release产物、未设置MTL_DEBUG_LAYER的一次记录如下，单位ms：

| 场景 | 首次提交总时间 | GPU中位数 | GPU p95 | 总时间中位数 | 总时间 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| red.pag | 5.974 | 0.582 | 3.296 | 8.697 | 11.563 |
| TEXT04.pag | 22.242 | 4.616 | 6.722 | 8.496 | 11.460 |
| ImageDecodeTest.pag | 1.575 | 0.372 | 3.018 | 8.632 | 11.226 |
| 两级整体透明组 | 12.894 | 1.381 | 4.112 | 8.300 | 11.268 |

总时间包含后台求值、资源准备、drawable等待、编码、GPU完成和actor恢复，不等于纯CPU编码时间。场景按表顺序运行，共享owner/管线；首次提交数据也可能受驱动着色器缓存影响，不是冷启动基准。GPU和总时间都受当前桌面负载影响，不能由这32帧推导最低iPhone或所有文件的稳定帧率。文字首帧准备明显高于暖帧，后续公开安装事务必须继续在后台准备，不挪入主线程。

复现性能探针：

```sh
PAG_METAL_BENCHMARK=1 \
CLANG_MODULE_CACHE_PATH=/tmp/pag-swift-clang-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/tmp/pag-swift-module-cache \
swift test -c release --disable-sandbox --cache-path /tmp/pag-swift-spm-cache \
  --filter MetalPlaybackBenchmarkTests
```

日志保留于`/tmp/pag-swift-p5-aa-full.log`、`/tmp/pag-swift-p5-aa-host.log`、`/tmp/pag-swift-p5-aa-benchmark.log`；iOS编译日志和目标文件在`/private/tmp/pag-swift-p5-aa-ios/`。
