# P5 整体透明度验收（阶段内检查点）

日期：2026-09-28。本记录接续[直接提交验收](P5直接提交验收.md)，完成必要局部组内容合成；**P5仍在进行中**，没有以本次GPU提交成功替代抗锯齿、最终画面或公开播放器验收。

后续覆盖接入已更新常量布局和裁剪绑定，见[覆盖接入验收](P5覆盖接入验收.md)；本文的80字节常量与硬边状态为该检查点历史记录。

## 已实现合同

- 不透明组展开到父pass，零alpha组跳过绘制资源，单个最终图元的组直接折入alpha。多个可能重叠图元保持自身alpha，先组合，再让组结果只乘一次整体alpha。
- `MetalFramePreparation`保留配对组栈、父裁剪与可见分配范围；嵌套局部pass按子先父后排列，根pass最后直接使用`drawable.texture`。普通帧仍只有一个直接显示pass。
- `RenderBounds`对缓存网格的实际Float顶点范围做Double四角变换，与显示/祖先裁剪的保守范围求交；附件向外保留一像素，再取整数区域。旋转裁剪仍保存真实逆变换行，没有以AABB替代。
- 整体alpha组的祖先/自身裁剪放在结果图元上，只应用一次；子内容自身的裁剪留在局部pass。关闭组恢复父状态，不污染后续兄弟图元。
- `MetalDrawUniforms`由64字节扩为80字节，追加当前pass原点。CPU在取得drawable前为各pass准备NDC；片元加回原点后在最终显示坐标执行裁剪。局部组纹理一比一合成，没有额外缩放、blit或CPU画面读回。

这是已有FramePlan整体alpha合同的实现，没有新增PAG字节布局、离屏出图API、依赖或另一套播放器。

## 附件预算与生命周期

`MetalGroupPool`在RenderOwner域内管理private BGRA8附件，用途只有renderTarget和shaderRead。活动与空闲池各默认64MiB，附件另计入单帧64MiB预算。按精确尺寸索引复用，空闲双向LRU按归还顺序淘汰，不扫描全部资源。

创建前先检查像素成本下界，创建后按`max(width × height × 4, allocatedSize) + 512`计费；复用直接使用已知成本。实际GPU占用超限时不发布借用。当前Xcode 27 SDK的`Metal.framework/Headers/MTLResource.h::allocatedSize`声明该属性为资源实际占用字节，避免把大量小纹理的页/块开销漏出预算。测试在实际分配高于像素成本时覆盖创建后的拒绝路径。

每次借用均产生新UUID，即使复用同一MTLTexture也不会复用旧身份。重复或迟到归还无效，已归还批次不能再次编码。准备失败会归还此前取得的全部附件；RenderOwner在等待真实GPU完成之后才归还已提交帧的附件。提交前撤销可直接放弃，仍沿既有MetalSubmissionCompletion的一次性出口处理，不因取消提前复用正在执行的GPU资源。

所有裸Metal资源保持在owner域，不新增`@unchecked Sendable`、`nonisolated(unsafe)`或跨actor裸纹理通道。
