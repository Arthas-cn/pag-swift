# P7 路径裁剪成本

2026-10-01，TrimPaths③内部成本门禁。源字段与曲线证据见[路径裁剪证据](P7路径裁剪证据.md)，阶段顺序见[架构设计](../架构设计.md)。正式tag25在本次测量时仍关闭，全部场景是明确的语义模型，不是伪造PAG文件。

## 环境与口径

- 主机Mac17,2，Apple M5，10核；macOS 27.0（26A428），Apple Swift 6.4（swiftlang-6.4.0.34.1），arm64，Release。
- 命令：在`packages/pag-swift`运行`PAG_TRIM_BENCHMARK=1 swift test -c release --filter TrimBenchmarkTests`。3项/1组通过，0.083秒，无编译诊断。日志`/tmp/pag-swift-p7-trim-benchmark-release.log`。
- 32/256是单路径上缘Line数量；x单调递增，上缘y交错20/30，底部闭合。每档分别验证staticPath、color、range，0...64帧轨道，动画采样1...32帧，每场32样本。范围从0...0.5逐渐扩大到0...0.9；静态/颜色保持0...0.5。
- 使用生产PreparedShapeStore四候选缓存和RenderGeometryCache。`staticPath`是同源同帧store命中代理，**不是PreparedScene安装后绕过动态actor的真实静态热路径**。准备时间含store调用，网格时间另计；不含GPU提交、显示等待或解码。
- “上中位数”取排序后第17项，p95取第31项，max取第32项；单次冷准备单独列出。每个场景在同一进程依次运行，冷数据不是多轮独立进程启动统计，不能据此推导严格线性扩展关系。测试断言和日志格式化位于计时区间外。
- 缓存、测量表、输出字节均为保守逻辑计量；允许共享数据重复计费。RSS为整个测试进程累计峰值，不是该场景净分配。CPU数值不能解释成播放帧率、GPU吞吐或长期真机表现。

## 预算与取消

256段已缓存样本以`estimatedBytes - 1`作新调用预算，明确抛`maximumFramePlanBytes`，单次拒绝CPU时间0.004375ms；缓存仍为92,688字节，再次正常请求返回原层身份。没有把缓存命中当作免费保活。

4096段范围动画worker发出启动信号后5ms请求取消。此次结果为`cancelled samples=15`，请求后0.008708ms退出，进程峰值RSS91,242,496字节。每次冷准备共享该次GeometryBudget；外层取消后等待worker结束，非取消生产错误继续抛出。信号只证明worker已启动，这个结果不证明固定在某个细分或切片步骤被打断，也不保证设备端最坏取消延迟。

## 显示与边界

成本探针与真实显示验收分开。同期32次挂载NSWindow drawable像素采样、五场景实际GPU三个buffer复用/失效/回帧恢复，以及生产RenderOwner取消/替换/迟到/resize通过，日志`/tmp/pag-swift-p7-trim-display-focused.log`，3项/3组，3.417秒。根pass直接绘制drawable；局部组alpha附件按原语义使用，成本实现没有增加整帧离屏拷贝或生产像素读回。

模式1仍没有真实文件；本次为源码语义、几何和像素覆盖。正式tag25、新增完整文件全帧及SwiftUI/UIKit/AppKit实际可见画面的门禁仍须按架构顺序继续。也尚未作上游逐帧金图或长期真机性能比较。
