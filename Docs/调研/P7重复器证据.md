# P7 Repeater 源码与真实资源证据

`include/pag/file.h::RepeaterOrder/RepeaterElement/RepeaterTransform`定义Below=0、Above=1及八条属性轨道；`src/codec/tags/shapes/Repeater.cpp::RepeaterTag`按order、copies、offset、anchorPoint、position、scale、rotation、startOpacity、endOpacity的顺序配置Value/SimpleProperty/SpatialProperty/MultiDimensionProperty。缺省值依次是0、3、0、(0,0)、(100,100)、(1,1)、0、255、255。`src/base/shapes/RepeaterElement.cpp`和`RepeaterTransform.cpp`均将所有轨道纳入变化范围。

`src/rendering/renderers/ShapeRenderer.cpp::ApplyRepeater`克隆当前组此前的全部已求值元素；负copies不改组，零copies清组，正数以`ceilf`计份。末份小数部分乘原组alpha，变换和start/end透明度按每份progress求值，Below按正序、Above按插前顺序排列。源函数没有只重复上一条路径的特殊规则。先前的Trim/Merge结果必须在克隆之前确定，重跑源元素可能改变路径长度与裁剪结果，不能当作等价实现。

`PAG_REPEATER_AUDIT=1`的调查器只沿已证实的文件、Vector、Layer、ShapeGroup标签边界读取tag26。126份当前资源中仅`repeater.pag`有一条40字节载荷：order=0、copies=5、offset=0、anchor=(0,24)、position=(0,0)、scale初值=(1,1)、rotation=0、start/endOpacity=255；**只有rotation有源帧0到30、0到72度的一段动画**，scale没有关键帧。调查器的`segments`按copies/offset/anchor/position/scale/rotation/start/end顺序输出，第六项的1属于rotation；曾把它误读成scale，已先修架构合同。该调查只证明字段布局和真实值，不证明完整解码或画面。在字段调查时，公开Loader已越过该文件首层无引用Track Matte，却仍明确失败于`layerTag:26`；后续实现与验收状态见本页末段。

内部生产读取器`readRepeaterProperties`已与独立调查器逐项核对这条真实子流；`RepeaterSampling`以源码Float份数、变换顺序和UInt8透明度规则产生有界复制描述符，负/零/2.5份、Above、锚点和预算**4项/1组定向通过**。这是接入源组前的历史子段；后续现状见下段。

现已在`ShapeContentPreparation`克隆当前组全部已求值节点，包含Trim后曲线的点列变换；此前所有Paint及路径均复制，零/负份数和Trim后不重新测量的3项语义测试通过。`repeater.pag`600源帧计划、600帧生产Metal准备及同一已挂载macOS drawable首帧/旋转中段像素差异通过，中段固定点RGBA为(1,136,251,255)。126资源重新分类为72/54，`repeater.pag`正式通过三时刻Metal输入，decoderRevision19。此处的稀疏像素和输入准备不等于Demo正式窗口的整帧可见验收，也不等于上游逐帧金图完全一致。
