额外严格策略先写入合同：正尺寸/有限正 fps/非零帧数、所有矩形非负且完整落在画布内；缺属性/缺序列/未知标签失败。上游 reader 对矩形坐标的裸指针写入不构成本库允许越界的理由。初批只支持系统可解码的静态 WebP、方向 1；不以其他图像解码器的容错当成 PAG 格式证据。解码预算先扣元数据与压缩载荷，像素按有界工作集采样时分配。

## 实现与验收

库内新增 `Loading/PAGBitmapDecoder.swift`、`Scene/SourceBitmap.swift`、`Media/BitmapFrameStore.swift`；共同 SourceComposition/FramePlanner 接入 bitmap，Metal 绘制器继续消费原有 FrameImage，没有增加整帧离屏 pass、blit 或 CPU 读回。载入不展开整片；媒体 actor 使用专用 DispatchSerialQueue executor，每次同步重建一个基底，系统调用前后及帧/矩形/行边界检查取消。缓存最多4条序列、工作预算64 MiB，FramePlan对动态输入保活另行计费。

真实文件 `RootLayerBitmap.pag`、Freeze、Offset 和 `small.pag` 全部完整载入；所选序列分别240、240、240、72帧，共792帧逐帧解码通过。未选分辨率仍验证字节与图像头，但未把全部低分辨率序列宣称逐帧像素已验收。Freeze/Offset 等文件实际还带外层 vector 合成；“RootLayer”文件名不能代替真实根类型。根 bitmap 的独立计划测试复用解码后的源合成构造语义图，不编造合法二进制。

`PAGBitmapTests`、`BitmapFrameTests` 覆盖原始偏移、计数/负坐标/截断损坏、预算、静态区间、半帧取整、末帧钳制、透明像素覆盖、跨关键帧/倒退 seek、旧输入不可变、相同帧命中、同序列两实例不同局部时间、失败与取消保留基底，以及条目/字节淘汰。透明覆盖的语义测试把真实1×1 WebP矩形移到已知有色像素上，不写出新PAG。完整库 `swift test` **388项、63组无失败**，日志 `/tmp/pag-swift-p7-full.log`。四个真实文件还接入 `MetalDrawableIntegrationTests` 的实际 drawable 提交；Metal调试层与CA主线程事务断言的专项日志为 `/tmp/pag-swift-p7-metal.log`。

demo 新增四个样例选项和可选 `--pag-sample=RootLayerBitmap.pag` 参数。Xcode Run 的 iOS 与 macOS 各通过原有7项有限宿主检查，使用实际库的刷新、快照、暂停与重挂，无独立业务时钟。iPhone Air（既有已启动模拟器，iOS27，UDID `7724380C-B1CB-4911-AB24-892AD286F4E9`）与macOS27在2,000,000微秒暂停；通过Xcode视图调试画面和macOS真实窗口观察，SwiftUI/UIKit/AppKit内容一致。macOS另手动播放并暂停在5,320,000微秒，SwiftUI/AppKit画面一致且较首帧有明确变化。验收启动参数与CA断言在共享scheme中均默认关闭。

可见检查限于上述时刻与宿主行为；未做792帧的上游逐像素金图对照。没有把源素材的CPU像素测试写成显示读回验收。macOS与iOS26部署目标均构建成功，最低系统26的实际ImageIO/显示运行仍待P9；当前系统27运行不能替代它。bitmap以外的内嵌video、重映射、其他P7经典内容与P8/P9合同继续保留，未扩大依赖或修改只读参考库。
