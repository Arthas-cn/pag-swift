# P4 内部播放状态机验收

2026-09-28。对应 [架构设计](../架构设计.md) 第5、10节与P4阶段表。**本阶段通过，可以进入P5直接Metal显示。** 当前没有公开PAGPlayer/PAGSurface或真正GPU提交器；这个结论只覆盖内部控制、调度、取消和状态观察，不表示已可播放。

## 合同与证据

| 合同 | 实现与验证 | 结果范围 |
| --- | --- | --- |
| 控制和状态 | PlaybackTimeline、PlaybackController；play/pause/stop/rewind/两种seek、总次数、缩放、缺少合成/表面 | 纯值和真实red.pag控制测试，无真实睡眠 |
| 正确时间与末帧 | 单调微秒、UInt128位置/整轮计算，倒序tick拒绝，单微秒/Int64.max/UInt64.max；自然终点只计一次 | 跳过旧待绘帧不拖慢时间，末帧完成前不发布finished |
| 隐藏与恢复 | 三态目标、冻结锚点、保留播放意图，主动暂停不会被窗口恢复覆盖 | hide/resume与末帧隐藏时的targetEpoch撤销均验证 |
| 有界调度 | 一个活动工作、一份最新pending；tick不取消正在完成的普通帧 | 三次tick合并成最后位置；旧工作未退出前不启动第二份活动工作 |
| 同步提交撤销 | PlaybackRequestToken完整五项身份、PlaybackSubmissionGate Mutex，withPermission串行提交段 | 每项身份、同步撤销、取消pending后禁止重新授权、完成许可只消费一次 |
| 不倒写新状态 | position由控制接受，presentedTime只收有效量化完成；新revision重新等首帧 | seek/缩放/resize/替换/清空之后旧完成不能更新新状态 |
| 显式render | 单次PlaybackRenderWaiter，与工作句柄分开；取消独立传播CancellationError | 活动/待处理取消立即返回、新控制取代取消、targetUnavailable不成为主错误 |
| 安装事务 | 真实PreparedScene后台准备、独立事务ID和任务句柄，保留旧完整场景直到新准备通过 | 逆序完成仅接收最新；更新安装与调用者取消都到达真实worker；失败不改变旧revision/位置 |
| 主错误与恢复 | 不可恢复错误冻结并发布failed，保留最后有效提交时间；普通控制继续抛原错误 | 有效同文档替换清错且保留位置；不同文档替换明确失败 |
| 状态流/释放 | 每位订阅独立bufferingNewest(1)、取消删除continuation；deinit撤销/取消/finish | 初值与最新值、订阅清理、活动工作不反向保活控制器均通过 |
| 执行域 | controller只做控制；PreparedScene和PlaybackWork明确后台执行；平台对象不跨域 | Swift6严格并发全库macOS测试与iOS26实际源码编译通过，无unchecked Sendable |

本阶段的播放计数/状态是新Swift合同，没有新增或猜测PAG字节。上游stop暂停、总重复次数等行为沿用既有 [libpag行为证据](libpag行为证据.md)。第5.3节明确了内部事务、有限末帧待提交、宽整数、UUID代数与恢复边界；没有机械翻译ObjC get/set。

## P5入口与尚未完成

- P5必须实现真正的PlaybackSubmitting owner，在后台求值/准备drawable/编码，最后通过同一gate临界区校验与enqueue/present。`submitted`只能在实际command buffer正常完成后返回。
- 显示bridge先做Swift6.4严格并发与生命周期探针，再接PAGSurface/PAGPlayer；主actor仅创建/挂载/布局/发送小值。生产显示时钟须与注入时钟使用同一单调原点，不能把任意平台绝对时间直接混入。
- 当前调度串行等待一次提交完成，满足最多一个活动工作及GPU最多2帧的上界；若P5/P9需要CPU/GPU重叠，必须保留代数、有限在途资源和取消合同，并重新验证，不无界追加Task。
- 真实目标直画drawable、形状/字形几何、组合alpha、纹理和GPU错误尚未实现；不生成离屏替代结果。三种宿主在P6用同一显示核心验证。
- P7–P9的剩余PAG格式、外部视频替换、动图/占位/跑马灯和真实性能测量仍未完成。总体Swift重写目标继续进行，P4通过不是SDK完成。
