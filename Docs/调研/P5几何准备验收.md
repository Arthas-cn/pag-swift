# P5 几何准备验收（阶段内检查点）

日期：2026-09-28。本文记录几何准备与缓存，**不表示P5通过，也不表示已经显示PAG画面**。

## 合同与实现范围

先在《架构设计》6.2补充几何精度、nonzero复合填充、预算与缓存合同，再实现：

| 文件 / 符号 | 已落实的职责 |
| --- | --- |
| `Rendering/RenderGeometry.swift`：RenderMesh、GeometryPrecision、GeometryBudget | 不可变相对原点三角形；最大奇异值决定2的幂次精度档；字节/工作量/深度限制 |
| `Rendering/PathFlattening.swift`：PathFlattening | 二次/三次曲线的de Casteljau细分；解析圆角按弓高界细分；保留绕序和隐式闭合 |
| `Rendering/NonzeroTessellation.swift`：NonzeroTessellation | 在顶点和线段交点处切分扫描带，以有符号绕数生成内部不重叠的填充三角形 |
| `Rendering/RenderGeometryCache.swift`：RenderGeometryCache | 64 MiB默认有界LRU，保活来源身份，复用相同路径/精度，平移不重新细分 |

以上都是internal渲染资源，没有新增public API、PAG字段、Package依赖或参考目录改动。输入来自P3已验证的ShapeGeometry和GlyphOutline；这是渲染算法，不是`.pag`字节布局证据。没有CPU最终画面栅格化、像素读回、整屏帧缓存或离屏出图API。

每次准备默认64 MiB保守逻辑字节、16,777,216工作单位、曲线最多32次二分。检查发生在增长/排序/扫描之前；取消与失败不返回部分资源。缓存命中同样检查当前预算和取消。超出缓存预算的合法网格可返回给调用者但不留存，零缓存预算明确禁用留存。缓存条目必须保活原始不可变对象，防止ObjectIdentifier地址复用误命中。

局部曲线容差为`1/8 / 2^precisionExponent`；形状内部组矩阵另外收紧源圆角容差。最终编码必须先补回RenderMesh.origin，再应用最终图层/字形矩阵。精度档不含平移、颜色或透明度。网格本身尚不包含抗锯齿覆盖值。

## 发现并修正的数值问题

圆形圆角测试曾报`geometryPrecision`：不同象限独立调用sin/cos会产生末位不对称，导致非常接近的扫描高度；两个相邻Double之间没有可表示的y中点。先在架构记录处理方式，再修改实现：

- 圆弧方向通过第一象限和轴对称复用，45度方向使用同一个数值。
- 扫描带以边上下端点的x平均值排序；均值相同时再按端点排序，只有两端均重合才合并绕数。不要求可表示的y中点，不丢弃窄带。
- 相交高度舍入引起的端点反序仅在32 ULP范围内允许折叠；更大反序明确失败，不能继续发布错误填充。

添加相邻Double扫描高度、20组圆角/旋转/斜切组合回归。这里的浮点策略属于实现合同，没有更改源路径绕序或填充规则。
