## 字段布局

`src/codec/tags/shapes/ShapePath.cpp::ShapePathTag`配置一个SimpleProperty<PathHandle>，默认是非nil空PathData。`src/codec/Attributes.h::AttributeConfig<PathHandle>`使用SingleEaseKeyframe，单值读取调用ReadPath，列表逐项调用同一读取器。动画头、n+1时间及缓动来自`AttributeHelper.h::ReadKeyframes/ReadTimeAndValue/ReadTimeEase`；属性是单维时间缓动。

`DataTypes.cpp::ReadPath`先读encoded UInt32记录数量。数量0直接返回空路径；非零时连续读取全部3位records，再读5位width-1，没有中间对齐。每个坐标读取补码有符号位值，再用Float乘SPATIAL_PRECISION=0.05。

| record | 展开的verb与点 |
| --- | --- |
| 0 Close | 一个close，无点；压缩lastX/lastY不变 |
| 1 Move | 一个move，读取x/y作为新端点 |
| 2 Line | 一个line，读取x/y作为新端点 |
| 3 HLine | 一个line，只读取x，沿用原y |
| 4 VLine | 一个line，只读取y，沿用原x |
| 5 Curve01 | 一个cubic，第一控制点用上一端点，再读取第二控制点和新端点 |
| 6 Curve10 | 一个cubic，读取第一控制点和新端点，第二控制点与新端点相同 |
| 7 Curve11 | 一个cubic，依次读取两个控制点及新端点 |

下一次ReadPath的encoded UInt32会字节对齐；最后一个动画路径之后的ReadTimeEase从剩余位紧接读取。实现不能在ReadPath返回时统一align，否则会丢掉真实缓动头。SourcePath按规范化verbs和独立points保存，move/line/cubic/close分别消费1/1/3/0点；数量及有限性在发布前验证。

## 形变与严格边界

`src/base/PathData.cpp::interpolate`与`GetCurveData`证明：任一端路径为空时，不写任何插值结果；非空同verb逐点插值。line与cubic不同时，把line的控制点设为上一端点和本段端点，输出cubic。`src/base/utils/Interpolate.h::Interpolate<Point/float>`按Float的`a + (b - a) * t`执行，本库在计算后才扩为Double，没有用Double中间运算或钳制Bezier的overshoot。

上游非空路径拓扑不匹配时可能直接越界，本库先按架构中的严格策略验证：非Hold段的verb数量必须相等，差异只允许line/cubic，且双方已有前点。move/close配对差异不补点、不截断，返回invalidFile。Hold不执行形变，允许两端不同拓扑；时间端点、常量与Hold直接共享不可变SourcePath，严格段内才计费并生成新路径。零跨度沿已有PropertyEvaluation端点优先规则，不进入除零计算。

读取前检查当前载荷至少能够放下records与位宽；记录数组、规范化指令/点及对象先扣DecodeBudget。插值输出计入FramePlanBudget；共享常量/端点不重复分配点。输入读取、布局验证、拓扑配对和插值长循环均检查取消，没有新增actor、平台对象、unchecked Sendable或UI工作。
