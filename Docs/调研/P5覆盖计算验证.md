## 实现与接口边界

`RenderCoverageIndex.prepare`为已有nonzero不重叠三角形建立不可变BVH。它以实际上传的Float坐标包围三角形，原位中位数划分，每叶最多4个三角形。节点按前序排列，保存子树出口下标；GPU不用递归栈即可跳过不相交子树。每个三角形只进入一个叶子，没有按网格跨格次数膨胀的候选数组。32字节节点与UInt32三角形索引是内部输入，不是PAG文件布局。准备使用64MiB、16,777,216逻辑工作量限制，并检查取消。

`RenderClipPolygon`从有界显示范围开始，将真实变换矩形逐个求凸交集，负scale通过绕序处理。它保留旋转边界，去掉重复相邻点，空交集与退化线/点不产生区域。`packedEdges`输出`float4(start.x,start.y,end.x,end.y)`数组；**返回空数组表示空交集，消费者必须跳过绘制**，不能把它转成着色器的“无额外裁剪”参数。

`MetalCoverageMath.source`提供可由片元共享的MSL函数：

- `pagTriangleArea`用三条有向边在单位像素中的Green积分计算面积。对`clamp(x,0,1)`做分段线性积分，同一区间单独处理，避免大而相近的数相减。
- `pagClippedTriangleArea`先判断完整凸裁剪是否包含或排除整个像素；边界相交时，对三角形、裁剪区域、像素三者共同求交。不能把两个独立覆盖率相乘，否则重合边会被重复衰减。
- `pagIntersectionArea`保留三个输入多边形处于其余区域内的边段，再累计边界积分。同向重合边按三角形、裁剪、像素的固定来源优先级只计一次；反向重合表示零面积交集。Float舍入合并的短边不排除整份内容，但全部裁剪边退化时返回零覆盖。
- `pagMeshArea`将像素范围逆变换为局部查询范围，用BVH筛选候选，再累计同一填充的面积，最后钳到0...1。原点补偿应由调用方在Double中完成；传入的horizontal/vertical是世界变换两行，inverse是逆线性矩阵。函数不混合颜色，也不创建或写入任何纹理。

面积和空间索引算法是本库渲染实现选择，不增加`.pag`字段支持。Apple的[MSAA示例](https://developer.apple.com/documentation/metal/improving-edge-rendering-quality-with-multisample-antialiasing-msaa)说明了多采样与resolve路径；本合同采用单采样目标中的覆盖计算，后续接入仍保持最终颜色附件为drawable，不增加固定整屏附件或播放像素读回。

## 验证证据

完整`swift test`报告**337项、52组、无失败**，其中13项GPU测试在沙箱明确跳过。随后同一测试产物以主机权限、`MTL_DEBUG_LAYER=1`、`--skip-build`运行`MetalCoverageMathTests|MetalDrawableIntegrationTests|MetalResourcesTests|DisplayTargetIntegrationTests|MetalGroupTests`，**13项全部实际通过**，Metal API Validation没有报错。

新增11项测试：

- BVH的空间查询与穷举范围一致，源三角形恰好保留一次，子树出口前进；重复中心、Float舍入、非法输入、内存/工作量上限及入口取消均覆盖。
- 凸裁剪重复加入不缩小区域；旋转/反射交集逐点对照原始矩形逆变换；相离、仅共享边、奇异矩阵和预算失败均覆盖。
- GPU直接三角形覆盖测试包含**5,670个标量样本**：斜边、细三角形、反向绕序、重复/旋转/反射裁剪、像素边重合与Float退化小裁剪。参照使用独立Double多边形裁剪后求鞋带面积，与生产GPU边段积分算法不同。
- TEXT04前两个真实字形的fill/stroke，共4份网格，在单位及镜像/错切/平移变换下验证**2,048个像素覆盖标量**。GPU执行实际BVH查询与候选三角形面积求和，CPU参照穷举实际Float三角形；样本绝对误差均小于`1e-4`。

GPU数值测试只使用输入buffer与覆盖标量buffer，没有颜色纹理、截图、最终帧像素或公开读回接口。既有真实窗口回归仍验证基础图元及嵌套组提交，使用的显示路径尚未切到新内核。
