# 实现规范模板

给另一个 Agent 的文档用这个骨架。章节可按模块删减，但不要删「职责」「公开合同」「非目标」「验收」。

文首固定四行元信息：

```markdown
# {模块名}：Agent 实现规范

> Swift 6.4 · iOS 26 · macOS 26 · 无第三方运行时依赖，除非本文另写
>
> 面向实现 Agent 的规范。面向使用者的说明可另文。本文是待实现的 API 与行为合同，不是已完成 SDK。
```

## 1. 目标、现状与职责

- 仓库里现在有什么。实现时不得把本文签名当成已编译 API。
- 库负责什么；**demo 负责什么**。用表格对照。
- 首版范围；明确不包含的能力。
- 对照旧 PAG 的哪些职责。最终 Swift 类型名可以不同，但映射必须写出来。

## 2. 模块结构与依赖方向

- 建议分文件（一文件一职责，遵守 R9）。
- 依赖只能指向允许的方向。demo 不复制库的解码/渲染实现。
- 哪些类型 `public` / `package` / `internal`。

## 3. 公开合同

- 用表格或 Swift 签名给出必须实现的类型、初始化器、默认值。
- 签名不要写方法体。
- 跨并发边界：`Sendable`、隔离、取消如何传播。库核心默认 `nonisolated`。
- 错误类型与失败语义。
- 时间用微秒还是进度，必须在签名旁写清，二者不要混成一个无单位数值。
- 调用点必须符合 Swift API Design Guidelines（先读该 skill）。

## 4. 行为与时序

- 生命周期（创建、复用、停止、取消、表面释放）。
- 替换文本/图像后，哪些已提交帧必须失效。
- 没有的状态机写「首版不做」。

## 5. 文件格式证据

- 凡是按字节解释 `.pag` 的条款，给出上游 libpag 源码路径或 pag.io 文档位置。
- 没有证据的布局不要写进合同；写成「未实现，禁止猜测」。

## 6. 验收门槛

用表格：阶段 → 必须覆盖的场景。库用 `swift test`。需要真机或模拟器时只验收 demo，并走 `ios-device-destination`。

## 7. 给实现 Agent 的启动提示

复制并改数字：

```text
1. 只实现本文声明的公开合同与验收表；不要把未写进文档的能力加进来。
2. 遵守 AGENTS.md：Swift 6.4、iOS 26、macOS 26、R1/R8/R9。先读 pag-swift-rewrite。
3. 第三方 skill 与本文冲突时以本文和 AGENTS.md 为准。公开 API skill 不能用来跳过 internal 注释。
4. 库的验证用 swift test。未出现在「验收」中的能力视为非目标。
5. 没有上游证据的 .pag 字段不要实现成「先能跑」。
```
